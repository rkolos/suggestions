# TASK-2.1: CRUD Сервис Предложений

## Контекст и цель задачи

Мы завершили подготовку инфраструктуры и переходим к разработке **Блока 2 (Ядро бизнес-логики)**. Ядро (Domain Layer) должно быть полностью изолировано от транспортного слоя (HTTP-контроллеров или Discord-событий). Это значит, что сервисы принимают чистые данные (DTO/интерфейсы) и ничего не знают про объекты `Request` или Discord `Interaction`.

Первая задача этого блока — создание базового сервиса для управления сущностью Предложение (`Suggestion`). Этот сервис будет обеспечивать классические CRUD-операции (создание, чтение, обновление, удаление), строго соблюдая правило Multi-tenancy (изоляцию по `companyId`).

_Примечание: Логика смены статусов (State Machine) и интеграция с Discord вынесены в отдельные задачи (TASK-2.2 и TASK-4.4). Здесь мы реализуем только базовую работу с базой данных._

## Что нужно сделать разработчику (Action Items)

### 1\. Инициализация модуля

-   В директории `src/modules/suggestions/` создать `SuggestionsModule` и `SuggestionsService`.
-   Убедиться, что `SuggestionsModule` импортирует глобальный `PrismaModule` (если он не сделан `@Global()`) и экспортирует `SuggestionsService` для использования в других модулях (например, в Discord-модуле).

### 2\. Реализация методов `SuggestionsService`

В сервисе необходимо реализовать следующие методы, каждый из которых **обязан** принимать `companyId` в качестве первого аргумента для гарантии изоляции данных:

-   **`create(companyId: string, authorId: string, data: CreateSuggestionDto)`**
    
    -   **Lazy Create пользователя:** При первом обращении через REST с новым `X-User-Id` backend обязан создать минимальную запись в таблице `users` (id = authorId + placeholder для username), если такой записи ещё нет. Это предотвращает ошибки внешнего ключа (FK) при создании предложений или голосов. Вызов Lazy Create выполняется до вставки предложения (на уровне контроллера, сервиса или отдельного хелпера).
    -   Создает новую запись в БД.
    -   Генерирует уникальный `id`: для обычных предложений — префикс `sug_`; для официальных постов (`isOfficial: true`) — префикс **`prop-`**. Устанавливает **`type: "official_proposal"`** и **`isPinned: true`** для официальных постов.
    -   Генерирует `slug` на основе переданного заголовка (title) с проверкой уникальности в рамках компании.
    -   Если передано `isOfficial: true` (создается админом из Web UI), сразу задать статус `OPEN`. В противном случае статус по умолчанию `NEW`.
    -   Источник (`source`) задается в зависимости от того, откуда пришел вызов (`WEB` или `DISCORD`).
    -   После успешного сохранения эмитить доменное событие **`suggestion.created`** (EventEmitter2) с пейлоадом созданного предложения — требуется для AI-синхронизации (TASK-5.1).
-   **`findAll(companyId: string, query: GetSuggestionsFilterDto)`**
    
    -   Метод для получения списка предложений (для админ-панели и виджетов).
    -   **Обязательное условие:** в Prisma-запросе всегда должно присутствовать `where: { companyId }`.
    -   **Пагинация:** поддержка параметров **`page`** и **`limit`** (offset-based). Ответ всегда возвращать в формате **`{ items: T[], total: number, page: number, limit: number }`** для консистентности с API.
    -   **Фильтрация:** по `status` (массив статусов), `category`, `authorId`.
    -   **Сортировка:** по дате создания (`createdAt`) или по количеству голосов (`score`). _Важно: для подсчета голосов можно использовать агрегацию Prisma или вычислять поле `score` на лету из таблицы `votes`._
    -   **Формат ответа:** возвращать объект **`{ items: T[], total: number, page: number, limit: number }`** (стандарт пагинации для API).
-   **`findById(companyId: string, suggestionId: string)`**
    
    -   Возвращает детальную информацию о предложении по ID (с проверкой принадлежности к `companyId`).
    -   Должен включать связанные данные (через `include` в Prisma): информацию об авторе (username, avatar), общее количество `upvotes` и `downvotes`, а также данные о дубликатах (`mergedIntoId`).
    -   Если запись не найдена, выбрасывает исключение `NotFoundException`.
-   **`update(companyId: string, suggestionId: string, data: UpdateSuggestionDto)`**
    
    -   Обновляет текстовые поля (заголовок, описание, категорию).
    -   Если обновляется заголовок, `slug` также должен быть перегенерирован (с проверкой на уникальность в рамках компании, см. TASK-1.6).
    -   После успешного обновления эмитить доменное событие **`suggestion.updated`** (EventEmitter2) — требуется для AI-синхронизации (TASK-5.1).
-   **`updateDiscordIds(companyId: string, suggestionId: string, data: { discordMessageId?: string; discordThreadId?: string })`**
    
    -   Обновляет идентификаторы сообщения и/или ветки Discord в записи предложения. Вызывается из Discord-модуля (TASK-4.4, TASK-4.5) после публикации или создания ветки.
-   **`delete(companyId: string, suggestionId: string)`**
    
    -   **Hard Delete:** физически удаляет предложение из БД (используя `companyId` и `suggestionId` в условии `where`). Политика удаления — только физическое удаление с каскадом; soft delete не используется.
    -   Благодаря `onDelete: Cascade`, настроенному в TASK-1.6, связанные голоса и комментарии удалятся автоматически.

## Критерии выполнения (Definition of Done)

-   \[ \] Созданы модуль и сервис `SuggestionsService`.
-   \[ \] Реализован механизм Lazy Create: при первом обращении с новым `X-User-Id` создаётся минимальная запись в таблице `users`, чтобы не нарушать FK при создании предложений и голосов.
-   \[ \] Реализованы методы `create`, `findAll`, `findById`, `update`, `updateDiscordIds` и `delete`. Методы `create` и `update` эмитят события `suggestion.created` и `suggestion.updated`.
-   \[ \] **Критично:** Во всех методах сервиса Prisma-запросы содержат фильтр `{ companyId }`. Ни один метод не позволяет получить, изменить или удалить предложение чужой компании.
-   \[ \] Метод `findAll` поддерживает фильтрацию, сортировку и пагинацию.
-   \[ \] При запросе несуществующего ID метод `findById` выбрасывает понятную ошибку (которая будет перехвачена глобальным фильтром из TASK-1.7).
