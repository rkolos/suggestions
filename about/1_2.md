# TASK-1.2: Настройка Docker-инфраструктуры

## Контекст и цель задачи

Для локальной разработки микросервиса требуются база данных PostgreSQL и in-memory хранилище Redis. Чтобы не засорять локальную систему разработчика и гарантировать идентичность окружения у всех членов команды, мы используем Docker Compose.

В этой задаче необходимо создать конфигурацию `docker-compose.yml` и подготовить базовый `.env` файл, чтобы сервисы могли общаться друг с другом локально. Это **минимальный набор** для запуска с Docker; полный список переменных окружения описан в TASK-1.3. Согласно стандартам, примеры кода в задачах опущены — разработчику необходимо самостоятельно составить конфигурационные файлы на основе приведенных ниже требований.

## Что нужно сделать разработчику (Action Items)

### 1\. Создание `docker-compose.yml`

В корне проекта необходимо создать файл `docker-compose.yml`, в котором должны быть описаны следующие сервисы и ресурсы:

-   **Сервис базы данных (postgres):**
    
    -   Образ: `postgres:15-alpine` (использование легковесных образов обязательно).
    -   Политика перезапуска: `unless-stopped`.
    -   Порты: проброс стандартного порта `5432`.
    -   Переменные окружения: задать `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB` (например, `suggestions_db`).
    -   Volumes: примонтировать именованный том для сохранения данных БД.
    -   Healthcheck: настроить проверку доступности с помощью утилиты `pg_isready`, используя указанного пользователя и базу данных.
-   **Сервис кэша и очередей (redis):**
    
    -   Образ: `redis:7-alpine`.
    -   Политика перезапуска: `unless-stopped`.
    -   Порты: проброс стандартного порта `6379`.
    -   Volumes: примонтировать именованный том для сохранения данных кэша.
    -   Команда запуска (command): включить персистентность (например, `--save 60 1` и `--appendonly yes`), чтобы очереди BullMQ не очищались при перезапуске контейнера; уровень логирования `--loglevel warning`.
-   **Volumes (Тома):**
    
    -   Объявить именованные тома (например, `postgres_data` и `redis_data`), чтобы при выполнении команды остановки данные не удалялись.

### 2\. Игнорирование локальных данных

-   Убедиться, что в файле `.gitignore` нет конфликтов с `volumes`, если локальные директории будут маппиться напрямую (при использовании named volumes это безопасно).
-   Обязательно добавить в `.gitignore` файлы конфигурации окружения (например, `.env` и `.env.local`).

### 3\. Подготовка шаблона переменных окружения

В корне проекта создать файл `.env.example` (и использовать его для создания локального `.env`). В нем должны быть задокументированы следующие переменные:

-   `DATABASE_URL` — строка подключения к БД. Формат: `postgresql://USER:PASSWORD@HOST:PORT/DATABASE?schema=public`.
-   `REDIS_URL` — строка подключения к Redis. Формат: `redis://HOST:PORT`.
-   `PORT` — порт, на котором запустится приложение NestJS (например, 3000).

## Критерии выполнения (Definition of Done)

-   \[ \] В корне проекта присутствует валидный файл `docker-compose.yml` с описанными сервисами `postgres` и `redis`.
-   \[ \] Присутствует файл `.env.example` с необходимыми переменными для подключения (`DATABASE_URL`, `REDIS_URL`, `PORT`).
-   \[ \] Команда `docker-compose up -d` успешно скачивает образы и запускает контейнеры без ошибок.
-   \[ \] К базе данных можно успешно подключиться через сторонний клиент (DBeaver, DataGrip, pgAdmin) по локальному порту с кредами из конфигурации.
-   \[ \] Контейнеры сохраняют данные при перезапуске (проверка персистентности: создать таблицу, выполнить остановку и повторный запуск контейнеров, убедиться, что таблица сохранена).
