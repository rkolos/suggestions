# TASK-3.2: API Предложений (Suggestions Controller)

## Контекст и цель задачи

Основное приложение (Web UI / Admin Panel) должно отображать списки предложений, позволять модераторам редактировать их, менять статусы и создавать новые официальные посты от имени проекта.

Цель этой задачи — создать контроллер `SuggestionsController`, который будет принимать HTTP-запросы, валидировать входные данные (DTO) и передавать управление доменному `SuggestionsService` (написанному в TASK-2.1 и TASK-2.2), строго соблюдая изоляцию данных по `X-Company-Id`.

## Что нужно сделать разработчику (Action Items)

### 1\. Подготовка DTO (Data Transfer Objects)

С использованием `class-validator` и `class-transformer` создать следующие классы:

-   `GetSuggestionsFilterDto`: для параметров `GET /` запроса (query). Поля: **`page`** и **`limit`** (пагинация, offset-based), `status` (опциональный массив), `category` (опционально), `sortBy` (дата или голоса).
-   `CreateSuggestionDto`: поля `title`, `description`, `category`, опциональное логическое `isOfficial` и опциональное `authorId`. **Правило источника автора:** `authorId` в теле запроса допускается **только для админов** при `isOfficial: true` (создание от имени другого пользователя). Во всех остальных случаях автор берётся из заголовка **`X-User-Id`**.
-   `UpdateSuggestionDto`: опциональные поля для изменения текста (`title`, `description`, `category`).
-   `UpdateSuggestionStatusDto`: обязательное поле `status` (из Enum `SuggestionStatus`), **опциональное** поле `comment` (строка) для публичного ответа админа при смене статуса (см. TASK-2.2).

### 2\. Реализация `SuggestionsController`

-   Создать контроллер с роутом `@Controller('api/v1/suggestions')`.
-   Защитить весь контроллер глобальным гардом `@UseGuards(CompanyIdGuard)`.

### 3\. Эндпоинты чтения (GET)

-   **`GET /` (Список предложений):**
    
    -   Принимает `@CurrentCompany() companyId` и `@Query() query: GetSuggestionsFilterDto`.
    -   Вызывает `SuggestionsService.findAll` и возвращает ответ в формате `{ items, total, page, limit }` (см. TASK-2.1).
-   **`GET /:id` (Детали предложения):**
    
    -   Принимает `@CurrentCompany() companyId` и `@Param('id') id`.
    -   Вызывает `SuggestionsService.findById`. Если запись не найдена, выбрасывается `NotFoundException` (перехватывается глобальным фильтром).

### 4\. Эндпоинты записи (POST, PATCH, DELETE)

-   **`POST /` (Создание):**
    
    -   Принимает `@CurrentCompany() companyId` и `@Body() body: CreateSuggestionDto`.
    -   Вызывает метод `create`. При `isOfficial: true` сервис генерирует id с префиксом **`prop-`**, устанавливает **`type: "official_proposal"`** и **`isPinned: true`**, статус — `OPEN`. Возвращает созданный объект (в формате API: вложенные `content`, `lifecycle`, `metrics`, `author`).
-   **`PATCH /:id` (Редактирование текста):**
    
    -   Обновляет базовые поля (заголовок, текст, категория). Вызывает `SuggestionsService.update`.
-   **`PATCH /:id/status` (Изменение статуса):**
    
    -   Критически важный эндпоинт. Принимает тело с новым статусом (`UpdateSuggestionStatusDto`).
    -   Вызывает метод машины состояний `SuggestionsService.updateStatus` (из TASK-2.2), который инициирует сайд-эффекты (публикацию в Discord и т.д.).
-   **`DELETE /:id` (Удаление):**
    
    -   Полностью удаляет предложение из базы данных (Hard Delete).

-   **`GET /:id/discord-preview` (Discord Preview):**
    
    -   Возвращает тело (payload) для Discord webhook/embed — как предложение будет выглядеть в Discord. Используется кнопкой «Discord Preview» в детальной панели. Защищен `CompanyIdGuard`, принимает `@CurrentCompany()` и `@Param('id') id`.

### 5. Виджет и публичная страница (Open in Widget)

-   **`GET /:id/widget`** или **`GET /:id/public`:**
    -   Назначение: кнопка «Open in Widget» в детальной панели; возвращает данные для отображения предложения на публичной странице или ссылку на виджет. Используется для сценария голосования без входа в админку (см. POST `/:id/vote` в TASK-3.5).
    -   Защита: роут может быть публичным (без `CompanyIdGuard`) для виджета на сторонних сайтах, либо требовать заголовок `X-Company-Id` — зафиксировать выбранный вариант в согласовании с API (suggestions-api 04, 08).
    -   Формат ответа: по контракту API — либо JSON с полями предложения для виджета, либо объект с полем `url` / `widgetUrl` (ссылка на публичную страницу). Поддержка query-параметра `format=link` для возврата только ссылки — по спецификации suggestions-api.
    -   Связь: голосование на публичной странице выполняется через **POST** `/:id/vote` (upvote/downvote), реализованный в TASK-3.5.

### 6\. Интеграция с Swagger (Опционально)

-   Описать каждый эндпоинт декораторами OpenAPI (`@ApiQuery`, `@ApiResponse` и т.д.) для генерации документации.

## Критерии выполнения (Definition of Done)

-   \[ \] Создан `SuggestionsController`, покрывающий полные CRUD-операции для предложений.
-   \[ \] Все DTO имеют строгую валидацию (например, нельзя передать несуществующий статус).
-   \[ \] Абсолютно каждый метод контроллера извлекает `@CurrentCompany()` и прокидывает его в методы сервиса.
-   \[ \] Смена статуса выведена в отдельный роут (или четко отделена логически), вызывающий генерацию доменных событий (Event Emitter).
-   \[ \] Запросы без заголовка `X-Company-Id` отклоняются на уровне Guard-а.
