# TASK-5.2: Интеграция с AI (Поиск дубликатов)

## Контекст и цель задачи

Чтобы предотвратить засорение платформы повторяющимися идеями, основное приложение (Web UI) должно показывать пользователю похожие предложения _до_ того, как он нажмет кнопку "Создать". Также этот функционал критически важен для модераторов в панели управления при ручном слиянии (Merge) тикетов.

Внешний AI-микросервис умеет делать векторный поиск (RAG) и возвращать массив ID похожих предложений. Цель данной задачи — реализовать **два сценария** работы с дубликатами в REST API:

1. **Модалка создания:** **POST** `/api/v1/suggestions/similar` с телом `{ text }` — поиск похожих по произвольному тексту до отправки формы.
2. **Вкладка Duplicates на детальной панели:** **GET** `/api/v1/suggestions/:id/duplicates` — список дубликатов для конкретного предложения по его id (по тексту этого предложения); **POST** `/api/v1/suggestions/:id/dismiss-duplicates` — действие «похожих нет» (фиксация решения модератора).

## Что нужно сделать разработчику (Action Items)

### 1\. Доработка `AiIntegrationService`

В сервисе, созданном в TASK-5.1, необходимо добавить новый метод для синхронного запроса к AI:

-   `findSimilar(companyId: string, text: string): Promise<string[]>`
-   Метод должен делать `POST` (или `GET` с query-параметрами) запрос к AI-микросервису (например, `/rag/search`).
-   В теле запроса передавать `companyId` (чтобы искать дубликаты строго внутри одной компании) и `text` (заголовок + описание новой идеи).
-   Ожидаемый ответ от AI-сервиса — массив строк (идентификаторов `suggestionId`).
-   **Обработка ошибок:** В отличие от TASK-5.1, этот запрос синхронный. Если AI-сервис недоступен или отвечает с ошибкой таймаута, метод должен перехватить ошибку, залогировать её и вернуть **пустой массив** `[]`, чтобы не блокировать работу основного приложения (Graceful Degradation).

### 2\. Доработка `SuggestionsService`

-   Добавить метод (или переиспользовать существующий `findAll` с фильтром по `in: ids`), который принимает массив `ids` и `companyId`.
-   Метод должен возвращать массив полных объектов предложений (с авторами, статусами и счетчиками голосов).
-   **Важно:** Порядок предложений в ответе должен соответствовать порядку ID, который вернул AI-сервис (так как AI возвращает их отсортированными по релевантности / similarity score).

### 3\. Создание API Эндпоинта

-   В `SuggestionsController` (из TASK-3.2) добавить новый эндпоинт: `POST /api/v1/suggestions/similar` (используем POST, так как передаем длинный текст).
-   Защитить роут гардом `@UseGuards(CompanyIdGuard)`.
-   Принимать DTO с полем `text` (обязательная строка).
-   **Алгоритм контроллера:**
    
    1.  Вызвать `AiIntegrationService.findSimilar(companyId, text)`.
    2.  Если массив ID пуст — сразу вернуть пустой массив `[]`.
    3.  Если ID есть — вызвать `SuggestionsService` для получения данных из БД по этим ID.
    4.  Вернуть обогащенный массив предложений клиенту.

### 4. Эндпоинты вкладки Duplicates (по id предложения)

-   **`GET /api/v1/suggestions/:id/duplicates`:**
    -   Назначение: вкладка «Duplicates» на детальной панели предложения; возвращает список похожих предложений для уже существующего предложения с данным `id` (текст для поиска берётся из полей этого предложения). Ответ — массив с полями предложений и, при необходимости, Match Score (по контракту suggestions-api 05).
    -   Алгоритм: по `companyId` и `id` загрузить предложение; вызвать `AiIntegrationService.findSimilar(companyId, title + description)` (или отдельный метод для поиска по id); исключить из результата сам объект с `id`; вернуть обогащённый список из БД.
    -   Защита: `@UseGuards(CompanyIdGuard)`.

-   **`POST /api/v1/suggestions/:id/dismiss-duplicates`:**
    -   Назначение: кнопка «Похожих нет» — модератор фиксирует, что дубликатов не найдено или решение просмотрено. Тело запроса может быть пустым или с опциональными полями (по контракту API). Сохранить факт dismiss при необходимости (например, флаг или запись в БД), чтобы не показывать блок повторно.
    -   Защита: `@UseGuards(CompanyIdGuard)`.

## Критерии выполнения (Definition of Done)

-   \[ \] В `AiIntegrationService` реализован метод `findSimilar`, делающий запрос к AI.
-   \[ \] В `SuggestionsController` создан эндпоинт `/similar`.
-   \[ \] Эндпоинт возвращает полные данные предложений (заголовок, статус, голоса), а не просто сырые ID.
-   \[ \] Запрос строго изолирован по `companyId`.
-   \[ \] В случае падения AI-микросервиса (502 Bad Gateway, Timeout), наш эндпоинт `/similar` не падает с 500 ошибкой, а корректно возвращает пустой массив `[]` (Graceful Degradation) и пишет `error` в логи.
-   \[ \] Реализован **GET** `/api/v1/suggestions/:id/duplicates` — возвращает список похожих предложений для предложения с данным id (вкладка Duplicates).
-   \[ \] Реализован **POST** `/api/v1/suggestions/:id/dismiss-duplicates` — действие «похожих нет» для предложения :id.
