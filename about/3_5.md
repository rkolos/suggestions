# TASK-3.5: Расширенное API (Votes, Stats, Comments)

## Контекст и цель задачи

В процессе проектирования основного REST API мы покрыли базовые CRUD-операции. Однако для полноценной работы Web UI (особенно публичной части для пользователей и главной страницы админ-панели) нам требуются дополнительные специализированные эндпоинты.

Цель этой задачи — расширить существующие контроллеры (или создать новые), чтобы дать фронтенду возможность:

1.  Голосовать за идеи прямо с сайта (а не только из Discord).
2.  Редактировать и удалять ошибочные комментарии модераторов.
3.  Получать агрегированную статистику для дашборда (без необходимости выкачивать весь массив предложений).

## Что нужно сделать разработчику (Action Items)

### 1\. Эндпоинт голосования (Web Voting)

Поскольку `VotesService` и логика Toggle-голосования уже реализованы в TASK-2.3, нам нужно просто обернуть их в контроллер.

-   В `SuggestionsController` (или отдельном `VotesController`) добавить:
    
    -   **`POST /api/v1/suggestions/:id/vote`**
-   **Логика:**
    
    -   Принимает `@CurrentCompany() companyId`.
    -   Принимает `@Headers('x-user-id') userId` (или через кастомный декоратор `@CurrentUser()`, так как для голосования обязательно знать, кто голосует).
    -   Принимает тело: **`VoteDto`** с полем **`vote: "upvote" | "downvote"`** (строковый контракт по API Spec; числовой `type` 1/-1 в API не используется; маппинг в сервис — на уровне контроллера).
    -   Вызывает `VotesService.toggleVote(...)` и возвращает обновленные счетчики.

### 2\. Управление комментариями (Редактирование и Удаление)

В TASK-3.4 мы реализовали чтение и создание комментариев (вложенный ресурс `.../suggestions/:suggestionId/comments`). Редактирование и удаление выполняются по **плоскому** маршруту в рамках модуля suggestions: **`/api/v1/suggestions/comments/:commentId`** (`commentId` глобально уникален).

-   **`PATCH /api/v1/suggestions/comments/:commentId`**
    
    -   Принимает `@CurrentCompany() companyId` и `UpdateCommentDto` (новое тело комментария `body`).
    -   Проверяет в БД, что комментарий существует и принадлежит предложению в рамках данной компании.
    -   Обновляет текст комментария.
-   **`DELETE /api/v1/suggestions/comments/:commentId`**
    
    -   Принимает `@CurrentCompany() companyId`.
    -   Удаляет комментарий (если он существует и принадлежит компании).
    -   _(Опционально)_: Если это был публичный комментарий (`isInternal: false`), отправить событие в Discord-модуль. Для MVP достаточно обновить только в БД.

### 3\. Эндпоинт статистики (Dashboard Stats)

Для красивого дашборда фронтенду нужны цифры (агрегация).

-   Создать эндпоинт статистики в рамках модуля suggestions: **`GET /api/v1/suggestions/stats`** (в `SuggestionsController` или отдельном `StatsController` с префиксом `api/v1/suggestions`).
-   **`GET /api/v1/suggestions/stats`**
    
    -   Защищен `@UseGuards(CompanyIdGuard)`.
    -   Принимает `@CurrentCompany() companyId`.
-   **Логика сервиса:**
    
    -   Использовать агрегацию Prisma (`prisma.suggestion.groupBy` или выполнить несколько параллельных `count` запросов).
    -   Возвращать в объекте **`byStatus` все** значения перечисления `SuggestionStatus` (включая статусы с нулевым количеством), чтобы обеспечить консистентность интерфейса для фронта. Пример формата ответа:
        
        ```
        {
          "total": 150,
          "byStatus": {
            "New": 12,
            "Open": 80,
            "Duplicate": 0,
            "Planned": 0,
            "In Progress": 0,
            "Completed": 45,
            "Rejected": 13
          }
        }
        ```
        

## Критерии выполнения (Definition of Done)

-   \[ \] Реализован эндпоинт `POST /.../vote`, позволяющий юзерам голосовать через REST API, переиспользуя надежный `VotesService`.
-   \[ \] В `CommentsController` добавлены методы `PATCH` и `DELETE` для редактирования и удаления существующих комментариев с проверкой `companyId`.
-   \[ \] Реализован эндпоинт `GET /api/v1/suggestions/stats`, возвращающий агрегированную статистику по статусам предложений для текущей компании без загрузки самих предложений в память сервера. В `byStatus` присутствуют все значения статусов в формате Title Case (New, Open, Duplicate, Planned, In Progress, Completed, Rejected), включая нулевые.
-   \[ \] Все новые эндпоинты защищены `CompanyIdGuard`.
