# TASK-1.4: Интеграция Prisma ORM

## Контекст и цель задачи

Для взаимодействия с базой данных PostgreSQL мы выбрали Prisma ORM (согласно архитектурным стандартам из Блока 0). Prisma обеспечивает строгую типизацию, удобный механизм миграций и отлично интегрируется с TypeScript.

Цель этой задачи — установить необходимые зависимости, инициализировать конфигурацию Prisma в проекте и создать глобальный сервис (`PrismaService`) в NestJS, который будет управлять жизненным циклом подключения к базе данных. Саму схему данных (модели) мы будем описывать в следующих задачах, сейчас фокус только на интеграции инструмента.

## Что нужно сделать разработчику (Action Items)

### 1\. Установка и инициализация

-   Установить CLI-инструмент Prisma как dev-зависимость (`prisma`) и клиент Prisma (`@prisma/client`) как основную зависимость.
-   Инициализировать Prisma в проекте (командой `npx prisma init`). Это создаст папку `prisma` с файлом `schema.prisma` и обновит файл `.env`.

### 2\. Настройка `schema.prisma`

-   Убедиться, что в блоке `datasource` провайдером указан `postgresql`.
-   Убедиться, что URL базы данных берется из переменной окружения `DATABASE_URL`, которую мы валидируем на этапе старта приложения (из TASK-1.3).

### 3\. Создание `PrismaService`

-   В папке **`src/common/prisma/`** создать класс `PrismaService`, который наследуется от `PrismaClient`.
-   Реализовать интерфейс `OnModuleInit` из пакета `@nestjs/common`. В методе `onModuleInit` необходимо явно вызывать `$connect()`, чтобы устанавливать соединение с базой данных при старте приложения.
-   (Опционально) Настроить логирование запросов к БД внутри конструктора `PrismaClient` (например, выводить `query`, `info`, `warn`, `error` в зависимости от `NODE_ENV`).

### 4\. Создание и экспорт `PrismaModule`

-   Создать модуль `PrismaModule`, который регистрирует `PrismaService` как провайдер.
-   Экспортировать `PrismaService`, чтобы другие модули могли его использовать.
-   Пометить `PrismaModule` декоратором `@Global()`, чтобы сделать его доступным во всем приложении без необходимости импортировать его в каждый доменный модуль (по аналогии с `ConfigModule`).
-   Импортировать `PrismaModule` в корневой `AppModule`.

## Критерии выполнения (Definition of Done)

-   \[ \] В `package.json` добавлены зависимости `prisma` и `@prisma/client`.
-   \[ \] В корне проекта существует папка `prisma` с корректным файлом `schema.prisma`.
-   \[ \] Создан глобальный `PrismaModule` и сервис `PrismaService`, управляющий подключением к БД.
-   \[ \] При запуске приложения с поднятым Docker-контейнером PostgreSQL (из TASK-1.2) приложение успешно подключается к БД без ошибок таймаута или аутентификации.
