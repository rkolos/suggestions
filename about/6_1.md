# TASK-6.1: Инфраструктура E2E и Тестовый API

## Контекст и цель задачи

Для гарантии качества нашего микросервиса мы внедряем E2E (End-to-End) Smoke-тесты. Эти тесты не мокают базу данных — они запускают реальное приложение (или стучатся в уже запущенный контейнер) и выполняют цепочки HTTP-запросов, имитируя поведение Web UI.

Чтобы тесты были изолированными и могли выполняться параллельно или многократно, нам требуется механизм очистки данных (Teardown). Так как удалять записи по одной через API долго и сложно, мы создадим специальный "опасный" эндпоинт, доступный только в тестовой среде.

## Что нужно сделать разработчику (Action Items)

### 1\. Настройка E2E-окружения

-   Убедиться, что в проекте установлен `jest` и `supertest` (стандартно идут в комплекте NestJS в папке `test/`).
-   В `package.json` должен быть скрипт `test:e2e` (например, `jest --config ./test/jest-e2e.json`).
-   Подготовить файл `test/setup.ts` (или утилиту внутри тестов) со вспомогательной функцией-клиентом, которая будет автоматически генерировать уникальный `companyId` (UUID) для каждого тестового прогона и подставлять его в заголовки `X-Company-Id`.

### 2\. Реализация Тестового Эндпоинта (Teardown)

-   Создать контроллер `TestingController` (например, в модуле `app.module.ts` или отдельном `TestingModule`).
-   **Важно (Защита):** Модуль с `TestingController` должен регистрироваться в приложении **строго** при **`process.env.NODE_ENV === 'test'`**. Реализовать это через **условный импорт** в `AppModule`: проверять `process.env.NODE_ENV === 'test'` и в этом случае подключать `TestingModule`; в Production модуль не подключается.
-   Добавить эндпоинт: `DELETE /api/v1/testing/teardown`
    
    -   Метод принимает `@CurrentCompany() companyId`.
    -   Логика: Выполняет сырой SQL-запрос или транзакцию Prisma для удаления всех данных этой конкретной компании:
        
        ```
        await prisma.companyConfig.deleteMany({ where: { companyId } });
        // Каскадное удаление (onDelete: Cascade) из TASK-1.6 автоматически удалит все предложения, голоса, комментарии и баны, привязанные к этой компании.
        ```
        

### 3\. Базовый шаблон (Skeleton) для E2E тестов

-   В папке `test/` создать файл `suggestions.e2e-spec.ts`.
-   В блоке `beforeAll` инициализировать Nest-приложение (`Test.createTestingModule`).
-   Подготовить глобальные переменные для тестов:
    
    -   `companyId = uuidv4()`
    -   `userA_Id = 'discord_id_1'`
    -   `userB_Id = 'discord_id_2'`
-   Написать самый первый примитивный тест (Health Check):
    
    ```
    it('/health (GET) should return 200', () => {
      return request(app.getHttpServer()).get('/health').expect(200);
    });
    ```
    
-   В блоке `afterAll` сделать обязательный вызов нашего эндпоинта очистки:
    
    ```
    await request(app.getHttpServer())
      .delete('/api/v1/testing/teardown')
      .set('X-Company-Id', companyId)
      .expect(200);
    await app.close();
    ```
    

## Критерии выполнения (Definition of Done)

-   \[ \] В проекте настроен запуск E2E тестов (`npm run test:e2e`).
-   \[ \] Реализован защищенный эндпоинт `DELETE /api/v1/testing/teardown`, который удаляет все данные компании (тестируется каскадное удаление).
-   \[ \] Тестовый модуль и эндпоинт очистки недоступны в production (регистрация только при `NODE_ENV=test`).
-   \[ \] Написан базовый скелет тестов с хуками `beforeAll` и `afterAll` (с вызовом Teardown).
