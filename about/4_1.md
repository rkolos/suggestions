# TASK-4.1: Инициализация ShardingManager и Discord.js

## Контекст и цель задачи

Наше приложение позиционируется как SaaS-решение, и бот будет устанавливаться на множество Discord-серверов (Guilds). Discord API имеет жесткие лимиты на количество серверов, которые может обслуживать одно WebSocket-соединение. Если мы просто вызовем `client.login()` внутри NestJS, при достижении лимита серверов (обычно 2500) бот перестанет работать.

Для решения этой проблемы мы должны использовать `ShardingManager` из библиотеки `discord.js`. Цель этой задачи — разделить процесс запуска на две части:

1.  Главный процесс (Manager), который управляет шардами.
2.  Дочерний процесс (Shard), внутри которого уже поднимается наше NestJS-приложение.

## Что нужно сделать разработчику (Action Items)

### 1\. Установка зависимостей

-   Установить библиотеку `discord.js` (версии 14.x).
-   (Опционально) Установить библиотеку для интеграции Discord в NestJS, например `necord` или `nestjs-discord`, либо написать свой кастомный провайдер. Для MVP рекомендуется использовать `necord`, так как он предоставляет удобные декораторы для слеш-команд.

### 2\. Создание файла `sharding.ts` (Точка входа)

В корне проекта (рядом с `main.ts` или в папке `src/`) необходимо создать отдельный скрипт запуска менеджера шардов.

-   Импортировать `ShardingManager` из `discord.js`.
-   Указать в конфигурации менеджера путь к скомпилированному `main.js` (файлу запуска NestJS).
-   Передать токен бота из переменных окружения (`process.env.DISCORD_BOT_TOKEN`).
-   Настроить обработчик событий менеджера (например, `manager.on('shardCreate', shard => console.log(...))`), чтобы видеть в логах, как запускаются дочерние процессы.

### 3\. Обновление `main.ts` (NestJS)

Файл `main.ts` больше не является абсолютной точкой входа всего сервиса при деплое. Теперь его будут вызывать шарды.

-   Убедиться, что NestJS корректно стартует (HTTP-сервер и API по-прежнему должны работать в каждом шарде, так как балансировщик нагрузки перед контейнерами сам распределит HTTP-запросы).

### 4\. Создание `DiscordModule`

-   Создать модуль `src/modules/discord/discord.module.ts`.
-   Настроить инициализацию Discord Client (или модуля `NecordModule.forRoot(...)`).
-   **Настройка Intents (Намерений):** Указать минимально необходимые интенты. Так как мы будем использовать в основном Slash Commands и Buttons (Interactions), нам понадобятся как минимум `GatewayIntentBits.Guilds`.
-   Внедрить `ConfigService` для безопасного получения `DISCORD_BOT_TOKEN` и `DISCORD_CLIENT_ID`.

### 5\. Обновление стратегии запуска

-   В `package.json` обновить скрипт `start:prod`, чтобы он запускал скомпилированный файл менеджера шардов (`node dist/sharding.js`), а не напрямую `main.js`.
-   Обновить конфигурацию Docker (созданную в Блоке 0), если это необходимо.

## Критерии выполнения (Definition of Done)

-   \[ \] В проекте установлена библиотека `discord.js`.
-   \[ \] Создан и настроен файл `sharding.ts` для управления шардами.
-   \[ \] Внутри NestJS (через `DiscordModule`) корректно инициализируется клиент Discord.
-   \[ \] При запуске приложения (через менеджер) в консоли появляются логи создания шарда (например, "Launched shard 0") и логи успешного подключения NestJS.
-   \[ \] Бот появляется в сети (Online) на тестовом сервере Discord.
