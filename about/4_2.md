# TASK-4.2: Маппинг контекста (Guild -> Company)

## Контекст и цель задачи

Вся наша бизнес-логика (сервисы, написанные в Блоке 2) и REST API строго завязаны на `companyId` для обеспечения изоляции данных (Multi-tenancy). Однако, когда пользователь взаимодействует с ботом в Discord (вызывает команду или нажимает кнопку), Discord API присылает нам `guildId` (ID сервера), а не наш внутренний `companyId`.

Цель этой задачи — создать связующее звено (Interceptor или Middleware для Discord-событий). Этот слой должен перехватывать **каждую** входящую интеракцию от Discord, извлекать из нее `guildId`, находить соответствующую компанию в базе данных и прокидывать её `companyId` дальше по цепочке выполнения, чтобы наши сервисы могли работать прозрачно.

## Что нужно сделать разработчику (Action Items)

### 1\. Создание слоя перехвата (Interceptor / Guard)

-   В модуле `src/modules/discord/` (или `src/common/`) создать класс перехватчика (например, `DiscordContextInterceptor` или `DiscordCompanyGuard`, в зависимости от используемой библиотеки, такой как `necord`).
-   Перехватчик должен извлекать объект `Interaction` из контекста выполнения (Execution Context).

### 2\. Логика маппинга (Guild ID -> Company ID)

Внутри перехватчика реализовать следующий алгоритм:

1.  Получить `guildId` из объекта интеракции. Если `guildId` отсутствует (например, команда вызвана в личных сообщениях бота), немедленно отклонить запрос, так как бот работает только на серверах.
2.  Сделать запрос в базу данных (через `PrismaService` или `CompanyConfigService`) для поиска записи `CompanyConfig`, где `discordGuildId` равен полученному `guildId`.
3.  **Обработка ненайденной компании:** Если сервер еще не зарегистрирован в нашей системе (нет привязки), бот должен ответить пользователю скрытым (Ephemeral) сообщением: _"Этот сервер еще не настроен. Пожалуйста, обратитесь к администратору для привязки сервера в панели управления."_ Дальнейшее выполнение обработчика команды должно быть прервано.
4.  **Успешный маппинг:** Если компания найдена, извлечь её `companyId`.

### 3\. Модификация контекста и декораторы

-   Прикрепить найденный `companyId` к текущему контексту запроса (например, мутировать объект интеракции или использовать `AsyncLocalStorage`), чтобы он был доступен внутри обработчиков команд.
-   Создать или адаптировать пользовательский декоратор (например, `@DiscordCompany()`), который будет извлекать этот `companyId` из контекста и передавать его аргументом в методы.

### 4\. Глобальное или точечное применение

-   Настроить применение этого перехватчика ко всем Slash-командам и обработчикам кнопок бота, чтобы разработчикам не приходилось вручную делать поиск по БД в каждой новой команде.

## Критерии выполнения (Definition of Done)

-   \[ \] Создан перехватчик/гард для маппинга Discord контекста.
-   \[ \] Перехватчик корректно обращается к базе данных и находит `companyId` по `discordGuildId`.
-   \[ \] При вызове команды на незарегистрированном сервере бот вежливо отказывает скрытым сообщением и не вызывает основную бизнес-логику (защита от мусорных данных).
-   \[ \] На зарегистрированном сервере `companyId` успешно извлекается и может быть получен в обработчике команды через декоратор.
