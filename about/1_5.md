# TASK-1.5: Схема БД (Часть 1: Базовые сущности)

## Контекст и цель задачи

База данных микросервиса должна поддерживать строгую изоляцию клиентов (Multi-tenancy) и хранить кэш профилей Discord-пользователей. Для этого нам требуются две базовые сущности: `CompanyConfig` (настройки конкретного сервера/компании) и `User` (пользователь, совершающий действия).

Цель этой задачи — описать эти две модели в файле `schema.prisma` и сгенерировать первую миграцию базы данных. Эти сущности станут родительскими для предложений, комментариев и голосов, которые мы опишем в следующей задаче.

## Что нужно сделать разработчику (Action Items)

### 1\. Описание модели CompanyConfig

В файле `schema.prisma` необходимо создать модель `CompanyConfig` (рекомендуемое имя таблицы в БД: `companies_config`). Эта модель будет хранить настройки интеграции для каждого клиента SaaS-платформы.

**Требуемые поля:**

-   `companyId` — первичный ключ (тип: `String`, сопоставление с `db.Uuid` в PostgreSQL). Передается из основного приложения.
-   `discordGuildId` — опциональная строка, уникальное поле (`@unique`). ID сервера в Discord, по которому мы будем мапить входящие вебхуки к конкретной компании.
-   `suggestionsChannelId` — опциональная строка. ID канала в Discord, куда бот будет публиковать карточки (Embeds) предложений со статусом Open.
-   `categories` — опциональное поле типа `Json` (значение по умолчанию: `[]`). Массив объектов категорий (например, `{ id, label, color }`).
-   `notificationTemplates` — опциональное поле типа `Json`. Шаблоны текстов для отправки в DM пользователям при смене статусов.
-   `createdAt` и `updatedAt` — стандартные поля времени создания и обновления.

### 2\. Описание модели User

Создать модель `User` (имя таблицы: `users`). Эта модель выполняет роль **глобального кэша** профилей Discord по Discord User ID: один и тот же пользователь может быть участником разных компаний, при этом в нашей системе он представлен одной записью в `users`. Запросы к Discord API при каждом рендере не требуются.

**Требуемые поля:**

-   `id` — первичный ключ (тип: `String`). В этой системе ID пользователя всегда равен его Discord User ID.
-   `username` — обязательная строка.
-   `avatarUrl` — опциональная строка (URL аватарки).
-   `lastSyncedAt` — обязательное поле даты/времени (по умолчанию равно `now()`). Используется для "ленивой" синхронизации (Lazy Sync) профиля с Discord API.

### 3\. Создание и применение миграции

-   После описания моделей выполнить команду для создания миграции в среде разработки (например, `npx prisma migrate dev --name init_base_models`).
-   Убедиться, что Prisma Client успешно сгенерировал типы для добавленных моделей.
