# TASK-3.3: API Массовых действий (Bulk Controller)

## Контекст и цель задачи

В реальной эксплуатации модераторам часто требуется обрабатывать несколько предложений одновременно: удалить пачку спама, перевести несколько идей в статус "Завершено" или слить группу похожих предложений в один оригинал. Делать это по одному запросу на каждое предложение — неэффективно с точки зрения сети и UX.

Цель этой задачи — создать отдельный контроллер (`BulkController`), который будет принимать массивы идентификаторов и выполнять групповые операции, соблюдая все правила безопасности и генерируя необходимые доменные события (Event Emitter).

## Что нужно сделать разработчику (Action Items)

### 1\. Подготовка DTO (Data Transfer Objects)

Создать следующие DTO для массовых операций (обязательно использовать `@IsArray()` и `@ArrayNotEmpty()` из `class-validator`):

-   `BulkDeleteDto`:
    
    -   `ids`: массив строк (идентификаторы предложений).
-   `BulkUpdateStatusDto`:
    
    -   `ids`: массив строк.
    -   `status`: обязательное поле (из Enum `SuggestionStatus`).
-   `BulkMergeDto`:
    
    -   `sourceIds`: массив строк (идентификаторы дубликатов).
    -   `targetId`: строка (идентификатор предложения-оригинала, в которое происходит слияние).

### 2\. Реализация `BulkController`

-   Создать контроллер с роутом **`@Controller('api/v1/suggestions/bulk')`** (внутри модуля `SuggestionsModule` или отдельного `BulkModule`). Эндпоинты: `POST /delete`, `POST /status`, `POST /merge` — итоговые пути `POST /api/v1/suggestions/bulk/delete`, `.../bulk/status`, `.../bulk/merge`.
-   Защитить контроллер глобальным гардом `@UseGuards(CompanyIdGuard)`.

### 3\. Эндпоинты массовых операций

-   **`POST /delete` (Массовое удаление):**
    
    -   Принимает `@CurrentCompany() companyId` и `@Body() body: BulkDeleteDto`.
    -   Логика: передать массив ID в сервис. В сервисе использовать `prisma.suggestion.deleteMany({ where: { id: { in: ids }, companyId } })`.
-   **`POST /status` (Массовое изменение статуса):**
    
    -   Принимает `@CurrentCompany() companyId` и `@Body() body: BulkUpdateStatusDto`.
    -   **Критический нюанс:** Изменение статуса вызывает сайд-эффекты (публикация в Discord, уведомления). Нельзя просто сделать `updateMany` в Prisma, так как нам нужно сгенерировать доменное событие для _каждого_ предложения.
    -   Логика: В сервисе перебрать массив `ids` и для каждого вызвать уже написанный метод `updateStatus` (из TASK-2.2). Желательно обернуть это в интерактивную транзакцию Prisma или использовать `Promise.allSettled`.
-   **`POST /merge` (Массовое слияние):**
    
    -   Принимает `@CurrentCompany() companyId` и `@Body() body: BulkMergeDto`.
    -   Логика: В сервисе перебрать массив `sourceIds` и для каждого вызвать написанный метод `mergeSuggestions` (из TASK-2.4).

### 4\. Доработка Сервисов (Service Layer)

-   Добавить соответствующие методы (`bulkDelete`, `bulkUpdateStatus`, `bulkMerge`) в `SuggestionsService`.
-   **Стратегия при частичной ошибке:** использовать **Partial Success**. При ошибке для части id не откатывать всю операцию: возвращать HTTP **207 Multi-Status** с массивом результатов по каждому ID (успех или ошибка по элементу), чтобы клиент и E2E-тесты могли обработать частичный результат.

## Критерии выполнения (Definition of Done)

-   \[ \] Создан `BulkController` с тремя эндпоинтами (`POST .../bulk/delete`, `.../bulk/status`, `.../bulk/merge`). При частичном успехе/ошибке возвращается 207 с массивом результатов по id.
-   \[ \] DTO строго валидируют массивы идентификаторов.
-   \[ \] Абсолютно все операции ограничены контекстом `@CurrentCompany() companyId` (невозможно удалить или обновить чужие данные).
-   \[ \] Массовое изменение статуса и массовое слияние корректно триггерят доменные события (`Event Emitter`) для каждого измененного предложения, чтобы Discord-бот мог обновить их статусы у себя.
