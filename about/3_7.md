# TASK-3.7: API текущего пользователя (GET /users/me)

## Контекст и цель задачи

Web UI и E2E-тесты (TASK-6.2) должны иметь возможность получить данные текущего пользователя по заголовку `X-User-Id`: например, для отображения профиля в шапке или для проверки того, что после действий пользователя его профиль сохранён в кэше (Lazy Sync).

Цель этой задачи — добавить эндпоинт **`GET /api/v1/users/me`**, возвращающий данные текущего пользователя из кэша (таблица `users`).

## Что нужно сделать разработчику (Action Items)

### 1. Эндпоинт и контроллер

-   В модуле `UsersModule` (или в отдельном контроллере, доступном по роуту `api/v1/users`) реализовать метод для **`GET /api/v1/users/me`**.
-   Защитить роут гардом `@UseGuards(CompanyIdGuard)` (при необходимости; для "me" достаточно проверки `X-User-Id` — уточнить, обязателен ли для этого роута контекст компании).
-   Извлекать идентификатор пользователя из заголовка **`X-User-Id`**. Если заголовок отсутствует — возвращать 400 Bad Request.

### 2. Контракт ответа

-   При успешном запросе возвращать **HTTP 200** и тело в формате **расширенного контракта** (в соответствии с API Spec):
    -   **`{ id: string, username?: string, avatar_url?: string, role?: string, permissions?: { canManageSuggestionsConfig?: boolean, canPostOfficialProposal?: boolean, canBanUsers?: boolean } }`**
-   `id` — Discord User ID (то же, что передан в `X-User-Id`).
-   `username`, `avatar_url` — из записи в таблице `users` (могут отсутствовать, если пользователь ещё не синхронизирован).
-   **`role`** — роль пользователя в контексте компании (например `Admin`, `Manager`, `Owner`, `User`); источник — Gateway или локальная конфигурация.
-   **`permissions`** — объект прав для скрытия/показа кнопок Settings и «Post as Official» на фронте.

### 3. Логика

-   По `X-User-Id` выполнить поиск в таблице `users`. Если запись найдена — вернуть её поля; если не найдена — вернуть объект с `id` и пустыми/отсутствующими `username` и `avatarUrl` (либо 404 — на усмотрение, но для E2E в TASK-6.2 ожидается 200 с `id`).

## Критерии выполнения (Definition of Done)

-   \[ \] Реализован эндпоинт `GET /api/v1/users/me` (или `GET /api/v1/me`), возвращающий 200 и объект с полями `id`, `username?`, `avatar_url?`, `role?`, `permissions?`.
-   \[ \] Идентификатор пользователя берётся из заголовка `X-User-Id`.
-   \[ \] Эндпоинт используется в E2E (TASK-6.2) для проверки сохранения профиля после Lazy Sync.
