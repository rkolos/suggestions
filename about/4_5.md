# TASK-4.5: Управление ветками (Threads) и синхронизация комментариев

## Контекст и цель задачи

Чтобы обсуждения предложений не засоряли основной канал, Discord позволяет создавать ветки (Threads), привязанные к конкретным сообщениям. В нашей системе каждая опубликованная идея (Embed) должна автоматически получать свою ветку для комментариев пользователей.

Более того, когда администратор или модератор отвечает на предложение через Web UI (создавая комментарий с флагом `isInternal: false`), этот ответ должен транслироваться прямо в эту ветку в Discord от лица бота, чтобы пользователи видели официальную реакцию. А когда идея закрывается, ветка должна блокироваться (Lock), чтобы прекратить обсуждение.

## Что нужно сделать разработчику (Action Items)

### 1\. Автоматическое создание ветки (Thread)

Эту логику необходимо добавить в сервис публикации (`DiscordPublishService` из TASK-4.4) в момент **первой** отправки Embed-сообщения:

-   Сразу после успешного вызова `channel.send({ embeds: [embed] })` и получения объекта `message`, вызвать создание ветки:
    
    ```
    const thread = await message.startThread({
      name: suggestion.title.substring(0, 100), // Ограничение Discord на длину имени
      autoArchiveDuration: 1440, // 24 часа неактивности (или по выбору)
      reason: 'Обсуждение нового предложения',
    });
    ```
    
-   Вызвать **`SuggestionsService.updateDiscordIds(companyId, suggestionId, { discordThreadId: thread.id })`** (при необходимости передать также `discordMessageId`, если он ещё не был сохранён на шаге публикации).

### 2\. Синхронизация публичных ответов админа

-   Создать обработчик событий для новых публичных комментариев (например, `@OnEvent('comment.public.created')`).
-   В обработчике извлечь `discordThreadId` из предложения, к которому относится комментарий.
-   Если ID ветки есть, получить объект ветки (ThreadChannel) через Discord API (`client.channels.fetch(threadId)`).
-   Отправить в эту ветку сообщение от имени бота.
    
    -   Рекомендуется визуально выделить его, например, используя Embed или жирный текст: `**[ОФИЦИАЛЬНЫЙ ОТВЕТ от @{Имя Админа}]**\n{Текст комментария}`.

### 3\. Автоматическая блокировка ветки (Lock)

Эту логику нужно добавить в обработчик смены статусов (рядом с обновлением цвета Embed в TASK-4.4):

-   Проверить `newStatus`. Если он относится к "терминальным" (закрывающим) статусам: `COMPLETED`, `CLOSED`, `REJECTED`, `DUPLICATE`.
-   Получить ветку по `discordThreadId`.
-   Выполнить блокировку и (опционально) архивацию ветки:
    
    ```
    await thread.setLocked(true, 'Предложение закрыто/выполнено');
    await thread.setArchived(true);
    ```
    
-   Если статус меняется обратно на `OPEN` или `IN_PROGRESS` (например, админ передумал), ветку желательно "разблокировать" (`setLocked(false)`).

### 4\. Обработчик события слияния (suggestion.merged)

-   Подписаться на доменное событие **`suggestion.merged`** (генерируется в TASK-2.4).
-   В обработчике получить из пейлоада данные по дубликату (`source`) и оригиналу (`target`). Отправить в **ветку дубликата** (по `discordThreadId` предложения-источника) сообщение от бота о слиянии (например: _"Идея объединена с [Оригинал]"_ со ссылкой на оригинал). Это ожидается в E2E (TASK-6.5).

### 5\. Обработка ошибок

-   Если ветка была удалена вручную администратором Discord, вызов `client.channels.fetch` или `thread.send` выдаст ошибку `Unknown Channel`.
-   Обернуть эти вызовы в `try/catch`, залогировать предупреждение, но не позволять приложению упасть.

## Критерии выполнения (Definition of Done)

-   \[ \] При первой публикации предложения (статус `OPEN`) под сообщением автоматически создается ветка с названием идеи.
-   \[ \] Бот корректно сохраняет `discordThreadId` в базу данных.
-   \[ \] При создании публичного комментария через REST API (из Блока 3) бот успешно отправляет этот текст в соответствующую ветку Discord.
-   \[ \] При переводе предложения в статус `COMPLETED`, `CLOSED` или `REJECTED` бот автоматически блокирует (Lock) ветку от новых сообщений пользователей.
-   \[ \] Реализован обработчик `suggestion.merged`: в ветку дубликата отправляется сообщение о слиянии с оригиналом.
-   \[ \] Ошибки (например, ручное удаление ветки) корректно перехватываются.
