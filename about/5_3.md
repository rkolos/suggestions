# TASK-5.3: Фоновая синхронизация профилей (Lazy Sync)

## Контекст и цель задачи

В нашей базе данных (в таблице `users`) хранится кэш профилей Discord-пользователей: их ID, `username` и `avatarUrl`. Мы используем этот кэш, чтобы не делать запросы к Discord API каждый раз, когда нужно отрендерить список предложений или комментариев в Web UI.

Проблема в том, что пользователи часто меняют свои аватарки и никнеймы в Discord. Если мы никогда не будем обновлять наш кэш, картинки со временем перестанут загружаться (Discord инвалидирует старые ссылки на аватары).

Решение — **Lazy Sync (Ленивая синхронизация)**. Мы не будем писать тяжелый Cron-джоб, который перебирает всю базу. Вместо этого мы будем обновлять профиль пользователя в фоновом режиме _в тот момент, когда он сам проявляет активность_ (создает предложение, нажимает кнопку голосования), но не чаще, чем раз в 24 часа.

**Порядок выполнения:** TASK-5.3 реализуется **до** задач Блока 4 (Discord). Модуль `users` уже учтён в структуре проекта в TASK-1.1. Обработчики команд и кнопок в TASK-4.3 и TASK-4.6 будут вызывать `UsersService.syncProfile`.

## Что нужно сделать разработчику (Action Items)

### 1\. Создание сервиса управления пользователями

-   Если еще не создан, добавить `UsersModule` и `UsersService` (например, в `src/modules/users/`).
-   Внедрить `PrismaService` и клиент `discord.js` (из `DiscordModule`).

### 2\. Реализация логики `syncProfile`

-   Написать метод `syncProfile(userId: string): Promise<void>`.
-   **Алгоритм:**
    
    1.  Найти пользователя в БД по `userId`.
    2.  Если пользователь найден, проверить поле `lastSyncedAt`.
    3.  Если с момента `lastSyncedAt` прошло **менее 24 часов**, просто завершить выполнение (ничего не делать).
    4.  Если прошло более 24 часов (или если юзера вообще нет в базе):
        
        -   Сделать запрос к Discord API: `await client.users.fetch(userId)`.
        -   Извлечь актуальные `username` и URL аватарки (`user.displayAvatarURL()`).
        -   Использовать `prisma.user.upsert(...)` (или `update`), чтобы обновить данные в БД и установить `lastSyncedAt = new Date()`.
-   **Обработка ошибок:** Обернуть вызов `client.users.fetch` в `try/catch`. Если Discord API недоступен или вернул ошибку, просто залогировать её и прервать синхронизацию (это не должно ломать основное приложение).

### 3\. Интеграция в точки входа (Discord Interaction)

Теперь этот метод нужно вызывать в тех местах, где пользователи взаимодействуют с ботом.

-   В обработчике слеш-команды `/suggest` (из TASK-4.3) перед (или после) созданием предложения.
-   В обработчике кнопок голосования (из TASK-4.6).
-   **Критически важно (неблокирующий вызов):** Вызов `usersService.syncProfile(userId)` не должен блокировать ответ пользователю в Discord. Запускайте его асинхронно (в фоне или через очередь BullMQ — см. TASK-0.1), чтобы UI в Discord реагировал мгновенно, а аватарка обновлялась "вдогонку".

## Критерии выполнения (Definition of Done)

-   \[ \] Реализован `UsersService` с логикой проверки `lastSyncedAt` (24 часа).
-   \[ \] Метод `syncProfile` корректно получает свежие данные через `discord.js` и обновляет кэш в БД.
-   \[ \] Вызов синхронизации внедрен в обработчики команд и кнопок Discord-бота.
-   \[ \] Синхронизация работает в фоновом режиме (fire-and-forget) и не замедляет отклик бота на действия пользователя.
-   \[ \] Ошибки Discord API (например, таймауты) при синхронизации не приводят к 500 ошибке или падению приложения.
