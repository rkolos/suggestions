# TASK-4.3: Slash-команда и Modal Submit

## Контекст и цель задачи

Пользователи в Discord должны иметь удобный способ отправлять свои предложения. Для этого мы будем использовать стандартный механизм Discord — Slash-команды (команда `/suggest`) и всплывающие модальные окна (Modals) для ввода текста.

Цель этой задачи — реализовать обработчик команды, который покажет пользователю форму, и обработчик отправки этой формы, который вызовет наше ядро (доменный сервис `SuggestionsService`) для сохранения идеи в базу данных. При этом мы будем использовать маппинг контекста (из TASK-4.2), чтобы точно знать, к какой компании привязать эту идею.

## Что нужно сделать разработчику (Action Items)

### 1\. Реализация команды `/suggest`

-   В модуле `DiscordModule` (или специализированном `CommandsModule`) создать обработчик слеш-команды `/suggest`.
-   **Важно:** Эта команда не принимает аргументов напрямую. Ее единственная задача — вернуть в Discord ответ типа `Modal` (модальное окно).
-   Сконструировать модальное окно:
    
    -   Задать ему уникальный `customId` (например, `suggest_modal`).
    -   Добавить текстовое поле (TextInput) для заголовка: короткое, обязательное.
    -   Добавить текстовое поле для описания: многострочное (Paragraph), обязательное.
    -   (Опционально) Добавить выпадающий список или текстовое поле для категории, если это поддерживается настройками компании.

### 2\. Реализация обработчика `ModalSubmit`

-   Создать обработчик, который будет перехватывать отправку формы с `customId`, равным `suggest_modal`.
-   Применить к этому обработчику созданный ранее Guard/Interceptor из TASK-4.2, чтобы гарантировать извлечение `companyId`.

### 3\. Интеграция с бизнес-логикой

Внутри обработчика модального окна необходимо реализовать следующий алгоритм:

1.  Извлечь введенные пользователем данные (Заголовок и Описание) из объекта взаимодействия.
2.  Извлечь `companyId` (через декоратор `@DiscordCompany()`, реализованный в TASK-4.2).
3.  Извлечь `userId` (ID пользователя Discord, отправившего форму).
4.  **Ленивая синхронизация профиля:** Вызвать **`UsersService.syncProfile(userId)`** (реализован в TASK-5.3; TASK-5.3 выполняется до задач Блока 4). Метод сохраняет/обновляет кэш пользователя в таблице `users` с учётом ограничения 24 часа.
5.  Вызвать метод `SuggestionsService.create` (написанный в TASK-2.1), передав ему извлеченные данные:
    
    -   `companyId`
    -   `authorId` = `userId`
    -   `source` = `DISCORD`
    -   `title` и `description`
6.  **Ответ пользователю:** После успешного создания записи отправить пользователю скрытое (Ephemeral) сообщение об успехе: _"Ваше предложение успешно отправлено и находится на рассмотрении!"_.

_Примечание: Мы пока не публикуем предложение в канал. Оно создается со статусом `NEW`. Публикация произойдет, когда модератор переведет его в статус `OPEN` через админ-панель (или если настроена авто-публикация, что будет реализовано отдельно)._

## Критерии выполнения (Definition of Done)

-   \[ \] В боте зарегистрирована глобальная слеш-команда `/suggest`.
-   \[ \] При вызове команды в Discord открывается модальное окно с полями "Заголовок" и "Описание".
-   \[ \] При отправке модального окна данные корректно парсятся и передаются в `SuggestionsService.create`.
-   \[ \] Предложение успешно сохраняется в базе данных с правильным `companyId` и `authorId`.
-   \[ \] Пользователь получает подтверждающее Ephemeral-сообщение, при этом бот не выдает ошибку "Interaction failed".
