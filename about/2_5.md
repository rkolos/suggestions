# TASK-2.5: Сервис комментариев и модерации (Баны)

## Контекст и цель задачи

Для полноценного управления предложениями модераторам требуются два дополнительных инструмента:

1.  **Team Chat (Внутренние комментарии):** Возможность обсуждать идеи внутри команды админов без публикации этих обсуждений в публичный Discord-тред.
2.  **Блэклист (Модерация):** Возможность забанить пользователя, чтобы он больше не мог создавать новые предложения или голосовать в рамках конкретной компании.

Цель этой задачи — реализовать CRUD для комментариев и сервис для управления списком забаненных пользователей.

## Что нужно сделать разработчику (Action Items)

### 1\. Реализация `CommentsService`

-   Создать `CommentsModule` и `CommentsService` в папке `src/modules/comments/`.
-   Реализовать метод `create(companyId: string, suggestionId: string, authorId: string, body: string, isInternal: boolean)`:
    
    -   Проверить существование предложения и его принадлежность к `companyId`.
    -   Сохранить комментарий в БД.
    -   Если `isInternal === false` (это официальный публичный ответ админа), необходимо сгенерировать доменное событие (например, `comment.public.created` через `EventEmitter2`), чтобы Discord-модуль позже смог перехватить его и отправить сообщение в ветку Discord.
-   Реализовать метод `findBySuggestionId(companyId: string, suggestionId: string)`:
    
    -   Возвращает список комментариев (с пагинацией) для конкретного предложения.
    -   Должен включать данные об авторе (join таблицы `users`).

### 2\. Реализация `BansService` (Модерация)

-   Создать `BansModule` и `BansService` в папке **`src/modules/moderation/`**.
-   Реализовать метод `banUser(companyId: string, userId: string)`:
    
    -   Создает запись в таблице `banned_users`.
    -   Если пользователь уже забанен (возникает ошибка уникальности Prisma `P2002`), метод не должен падать с 500 ошибкой (она перехватится глобальным фильтром, но лучше обработать изящно и вернуть, например, `true` или бросить 409 Conflict).
-   Реализовать метод `unbanUser(companyId: string, userId: string)`:
    
    -   Удаляет запись из `banned_users`. Если записи нет — просто игнорирует (или бросает 404).
-   Реализовать метод `isBanned(companyId: string, userId: string): Promise<boolean>`:
    
    -   Проверяет наличие записи в таблице. Этот метод будет критически важен в будущем: мы будем вызывать его в Discord-боте перед тем, как позволить пользователю проголосовать или создать идею.
-   Реализовать метод `getBannedUsers(companyId: string)`:
    
    -   Возвращает список забаненных пользователей для отображения в админ-панели (с пагинацией и данными юзеров).

### 3\. Интеграция с существующими сервисами

-   Внедрить `BansService` в `SuggestionsService` и `VotesService`.
-   Перед тем как создать новое предложение (в `SuggestionsService.create`) или засчитать голос (в `VotesService.toggleVote`), добавить проверку `isBanned`.
-   Если пользователь забанен, выбрасывать доменную ошибку (например, кастомный `ForbiddenException` с кодом `USER_BANNED`), чтобы блокировать любые действия по изменению состояния.

## Критерии выполнения (Definition of Done)

-   \[ \] Созданы сервисы `CommentsService` и `BansService`.
-   \[ \] Внутренние комментарии (`isInternal: true`) корректно сохраняются и извлекаются с привязкой к `companyId`.
-   \[ \] Публичные ответы (`isInternal: false`) генерируют событие для Event Emitter.
-   \[ \] Модераторы могут банить и разбанивать пользователей (данные сохраняются в таблицу `banned_users`).
-   \[ \] Методы создания предложений и голосования защищены проверкой на бан (если юзер в блэклисте, операция прерывается с ошибкой).
