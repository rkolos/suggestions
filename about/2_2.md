# TASK-2.2: State Machine Предложений (Машина состояний)

## Контекст и цель задачи

В микросервисе жизненный цикл предложения управляется статусами (`NEW`, `OPEN`, `PLANNED`, `IN_PROGRESS`, `COMPLETED`, `CLOSED`, `REJECTED`, `DUPLICATE`). Переход из одного статуса в другой порождает побочные эффекты (сайд-эффекты).

Например, при переходе из `NEW` в `OPEN` предложение должно быть опубликовано в Discord, а при переходе в `COMPLETED` ветка обсуждения должна быть закрыта.

**Архитектурное ограничение:** Доменный сервис (`SuggestionsService`) ничего не должен знать о реализации Discord-бота. Поэтому вместо прямых вызовов (вида `discordBot.postMessage()`) сервис должен генерировать доменные события (Domain Events). Логику отправки сообщений в Discord мы напишем позже в Блоке 4, и она будет просто "слушать" эти события.

## Что нужно сделать разработчику (Action Items)

### 1\. Подключение Event Emitter

-   Установить пакет `@nestjs/event-emitter`.
-   Подключить `EventEmitterModule.forRoot()` в корневом `AppModule`.
-   Внедрить `EventEmitter2` в `SuggestionsService`.

### 2\. Реализация метода `updateStatus`

Добавить в `SuggestionsService` метод `updateStatus(companyId: string, suggestionId: string, newStatus: SuggestionStatus)`:

-   **Поиск и валидация:** Найти предложение по ID и `companyId`. Если не найдено — пробросить `NotFoundException`.
-   **Проверка перехода:** Убедиться, что новый статус отличается от старого. Если статусы совпадают, можно просто вернуть текущее предложение без лишних запросов к БД.
-   **Обновление в БД:** Обновить поле `status` в базе данных через Prisma.
-   **Генерация событий (Event Dispatching):** После успешного обновления в БД метод должен вызвать `eventEmitter.emit(...)` с соответствующим пейлоадом.

### 3\. Проектирование Доменных Событий (Domain Events)

Необходимо описать и типизировать события (например, создать классы/интерфейсы в `src/modules/suggestions/events/`):

-   **`suggestion.status.changed`**
    
    -   Универсальное событие. Должно содержать: `companyId`, `suggestionId`, `oldStatus`, `newStatus`, а также полный объект обновленного предложения.
-   **`suggestion.published`** (Опционально, для удобства)
    
    -   Выбрасывается конкретно при переходе из `NEW` в `OPEN`. Служит четким сигналом для Discord-модуля: "Создай новый Embed и Thread".

### 4\. Интеграция с официальными ответами

-   DTO смены статуса (в API — TASK-3.2) расширяется **опциональным полем `comment`**. Если при вызове `updateStatus` передано это поле, `SuggestionsService` (или контроллер) создает публичный комментарий с `isInternal: false` через `CommentsService`, что спровоцирует отправку сообщения бота в Discord-ветку (TASK-4.5).

## Критерии выполнения (Definition of Done)

-   \[ \] В проект интегрирован `@nestjs/event-emitter`.
-   \[ \] В `SuggestionsService` реализован метод `updateStatus`.
-   \[ \] Метод корректно обновляет статус в БД, учитывая изоляцию по `companyId`.
-   \[ \] При успешной смене статуса генерируется строго типизированное доменное событие (например, `suggestion.status.changed`).
-   \[ \] Создан тестовый слушатель (`@OnEvent('suggestion.status.changed')`) где-нибудь в системе (например, просто выводящий лог в консоль), доказывающий, что цепочка событий работает.
