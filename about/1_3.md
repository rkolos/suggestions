# TASK-1.3: Настройка конфигурации и переменных окружения

## Контекст и цель задачи

Микросервис зависит от множества внешних ресурсов (PostgreSQL, Redis, Discord API, внутренний AI-сервис). Если приложение запустится без необходимых переменных окружения, это приведет к непредсказуемым ошибкам в рантайме (например, при попытке сохранить данные или отправить вебхук).

Цель этой задачи — внедрить строгую валидацию файла `.env` на этапе старта приложения (Bootstrap). Если конфигурация невалидна, приложение должно немедленно завершать работу (Fail Fast) с понятным сообщением об ошибке в консоли. **Режим по окружению:** при `NODE_ENV=development` переменные Discord (`DISCORD_BOT_TOKEN`, `DISCORD_CLIENT_ID`) и AI (`AI_SERVICE_URL`) делаются **опциональными** — приложение стартует с предупреждением в логах; для Production они строго обязательны. Согласно нашим стандартам, конкретные примеры кода конфигурации опущены — разработчик реализует логику самостоятельно на базе `ConfigModule`.

## Что нужно сделать разработчику (Action Items)

### 1\. Подключение модуля конфигурации

-   Установить пакет `@nestjs/config`.
-   Интегрировать `ConfigModule` в корневой модуль приложения (`AppModule`).
-   Сделать конфигурационный модуль глобальным (`isGlobal: true`), чтобы не импортировать его в каждый отдельный бизнес-модуль.

### 2\. Реализация логики валидации

-   Выбрать инструмент для валидации: рекомендуется использовать связку `class-validator` и `class-transformer` (создание DTO для переменных окружения) или библиотеку `Joi`.
-   Настроить `ConfigModule` таким образом, чтобы при инициализации он прогонял все переменные из `process.env` через выбранный валидатор.
-   В случае провала валидации (отсутствует обязательное поле или неверный тип данных) процесс должен выбрасывать исключение и завершаться.

### 3\. Модель конфигурации (Обязательные поля)

Схема валидации должна строго требовать наличия следующих переменных:

-   **База данных и кэш:**
    
    -   `DATABASE_URL` — обязательная строка. Должна валидироваться как корректный URL.
    -   `REDIS_URL` — обязательная строка. Должна валидироваться как корректный URL.
-   **Приложение:**
    
    -   `PORT` — опциональное число. Значение по умолчанию: `3000`.
    -   `NODE_ENV` — опциональная строка (допустимые значения: `development`, `production`, `test`). По умолчанию: `development`.
-   **Discord Интеграция:** (обязательны в Production, опциональны в development — см. выше)
    
    -   `DISCORD_BOT_TOKEN` — строка.
    -   `DISCORD_CLIENT_ID` — строка.
-   **Внутренние API:** (обязателен в Production, опционален в development)
    
    -   `AI_SERVICE_URL` — строка (URL для отправки запросов к RAG).

### 4\. Доступ к конфигурации в сервисах

-   Убедиться, что разработчики смогут получать типизированный доступ к переменным окружения через внедрение `ConfigService` из `@nestjs/config`.

## Критерии выполнения (Definition of Done)

-   \[ \] В проект установлен и глобально подключен `@nestjs/config`.
-   \[ \] Описана схема валидации переменных окружения, включающая все обязательные поля (БД, Redis, Discord, AI API).
-   \[ \] Если запустить приложение с отсутствующим `DATABASE_URL`, оно крашится на этапе загрузки. В Production то же самое при отсутствии Discord/AI переменных; в development при их отсутствии — старт с предупреждением в логах.
-   \[ \] Если все переменные указаны корректно, приложение успешно запускается.
