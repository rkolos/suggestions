# TASK-4.4: Синхронизация Embed-сообщений

## Контекст и цель задачи

Когда модератор через веб-панель переводит предложение из статуса `NEW` в статус `OPEN`, пользователи Discord должны увидеть эту идею в специальном канале. При последующих изменениях статуса (например, на `IN_PROGRESS` или `COMPLETED`), опубликованное сообщение должно автоматически обновляться (менять цвет, добавлять плашку статуса), чтобы сообщество всегда видело актуальное состояние.

Цель этой задачи — реализовать сервис `DiscordPublishService`, который будет "слушать" доменные события от ядра (настроенного в TASK-2.2) и преобразовывать их в вызовы Discord API для создания или редактирования Rich Embed сообщений. **Реализация публикации:** вместо синхронного fire-and-forget использовать **очередь BullMQ** (см. TASK-0.1): регистрировать задачу на публикацию/обновление, обрабатывать её воркером, чтобы обеспечить retries и изоляцию от основного потока.

## Что нужно сделать разработчику (Action Items)

### 1\. Создание сервиса публикации

-   В модуле `src/modules/discord/` создать `DiscordPublishService`.
-   Внедрить в него клиент Discord (`Client` из `discord.js` или эквивалент из `necord`).
-   Внедрить `CompanyConfigService` (для получения ID канала) и `SuggestionsService` (для сохранения ID опубликованного сообщения).

### 2\. Подписка на доменные события

-   Импортировать декоратор `@OnEvent` из `@nestjs/event-emitter`.
-   Создать обработчик для события изменения статуса (например, `@OnEvent('suggestion.status.changed')`).
-   Обработчик должен принимать пейлоад: `companyId`, полный объект `suggestion`, `oldStatus` и `newStatus`.

### 3\. Логика публикации и обновления

Внутри обработчика события реализовать следующий алгоритм:

1.  **Проверка необходимости публикации:**
    
    -   Если `newStatus === 'NEW'`, публикация в канал не выполняется. Если `newStatus === 'DUPLICATE'`, сообщение в канале **обновляется** (Embed с новым статусом и ссылкой на оригинал), а **кнопки голосования удаляются** (ActionRow становится пустым или не передаётся).
2.  **Получение настроек:**
    
    -   Запросить `CompanyConfig` по `companyId` и получить `suggestionsChannelId`.
    -   Если канал не настроен, прервать выполнение (ошибка конфигурации, логируем предупреждение).
3.  **Генерация Embed:**
    
    -   Создать объект `EmbedBuilder` (из `discord.js`).
    -   Заполнить его данными:
        
        -   **Title:** Заголовок предложения.
        -   **Description:** Текст предложения (ограничить длину, если нужно).
        -   **Author:** Никнейм и аватарка автора (берем из связи с таблицей `users`).
        -   **Color:** Зависит от статуса (например, желтый для `OPEN`, синий для `IN_PROGRESS`, зеленый для `COMPLETED`).
        -   **Footer / Fields:** Вывести текущий статус в виде красивого текста.
4.  **Отправка или Редактирование:**
    
    -   Проверить поле `suggestion.discordMessageId`.
    -   **Если ID нет (Первая публикация):**
        
        -   Найти канал Discord по `suggestionsChannelId`.
        -   Отправить сообщение с собранным Embed (`channel.send({ embeds: [embed] })`).
        -   Вызвать **`SuggestionsService.updateDiscordIds(companyId, suggestionId, { discordMessageId: message.id })`** (метод из TASK-2.1).
    -   **Если ID есть (Обновление):**
        
        -   Найти канал и затем найти само сообщение по `discordMessageId`.
        -   Отредактировать сообщение (`message.edit({ embeds: [embed] })`).

### 4\. Обработка ошибок Discord API

-   Если боту не хватает прав на отправку сообщений в канал, или если сообщение было удалено вручную, Discord API выбросит ошибку.
-   Обернуть вызовы `send` и `edit` в `try/catch`. При ошибке выполнять только **логирование** через `Logger.error` (не крашить приложение). Дополнительные флаги или изменения в БД не требуются.

## Критерии выполнения (Definition of Done)

-   \[ \] В `DiscordModule` создан `DiscordPublishService`, подписанный на события Event Emitter.
-   \[ \] При переводе предложения в статус `OPEN` (например, через REST API из Блока 3) в указанный в настройках канал автоматически отправляется Rich Embed.
-   \[ \] Бот корректно сохраняет `discordMessageId` в базу данных после первой публикации.
-   \[ \] При дальнейшей смене статуса (например, на `COMPLETED`) уже существующее сообщение обновляется (меняется цвет и текст статуса в Embed), а не создается новое.
-   \[ \] Ошибки Discord API (нет прав, канал удален) корректно перехватываются и логируются.
