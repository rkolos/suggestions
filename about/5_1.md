# TASK-5.1: Интеграция с AI (RAG Sync)

## Контекст и цель задачи

Наше приложение должно помогать модераторам находить дубликаты предложений с помощью искусственного интеллекта (RAG - Retrieval-Augmented Generation). Чтобы AI-микросервис "знал" о наших предложениях, мы должны отправлять ему данные каждый раз, когда создается новая идея или обновляется текст существующей.

Цель этой задачи — реализовать интеграцию с AI-микросервисом: подписаться на доменные события ядра и отправлять данные в AI в фоновом режиме. Вместо fire-and-forget использовать **очередь BullMQ**: регистрировать задачу на синхронизацию (RAG sync), обрабатывать её воркером — это обеспечит retries и изоляцию от основного потока (см. TASK-0.1).

## Что нужно сделать разработчику (Action Items)

### 1\. Подготовка модуля интеграции

-   Создать `AiIntegrationModule` и `AiIntegrationService` в папке **`src/modules/ai-integration/`** (согласовано со структурой из TASK-1.1).
-   Для выполнения HTTP-запросов рекомендуется установить и подключить `@nestjs/axios` (модуль `HttpModule`) или использовать встроенный в Node.js 20 `fetch`.
-   Внедрить `ConfigService` для получения URL AI-микросервиса (`AI_SERVICE_URL`).

### 2\. Подписка на доменные события

-   В сервисе `AiIntegrationService` создать обработчики (Listeners) для событий создания и обновления предложений (например, `@OnEvent('suggestion.created')` и `@OnEvent('suggestion.updated')`).
-   Убедиться, что доменный `SuggestionsService` (созданный в TASK-2.1) корректно генерирует эти события при вызове методов `create` и `update`.

### 3\. Реализация фоновой отправки (очередь BullMQ)

-   Вместо прямого HTTP-вызова из обработчика события добавлять задачу в очередь BullMQ (например, очередь `ai-sync`). Воркер этой очереди формирует payload и выполняет запрос. Рекомендуемая структура payload:
    
    ```
    {
      "suggestionId": "sug_123",
      "companyId": "uuid-компании",
      "title": "Заголовок",
      "description": "Описание идеи",
      "status": "OPEN"
    }
    ```
    
-   Выполнить HTTP `POST` запрос (или `PUT` для обновления) на эндпоинт AI-сервиса (например, `${AI_SERVICE_URL}/rag/sync`).
-   **Критически важно:** Регистрация задачи в очередь не должна блокировать ответ пользователю; обработка (HTTP-запрос к AI) выполняется воркером в фоне.

### 4\. Обработка ошибок изоляции

-   AI-микросервис может быть недоступен (упал, перезагружается, таймаут). Наше основное приложение **ни при каких обстоятельствах не должно падать** или выдавать 500 ошибку пользователю из-за сбоя внешней интеграции.
-   Обернуть HTTP-вызов в `try/catch`.
-   При ошибке запроса просто залогировать ее через `Logger` (уровня `error` или `warn`), чтобы разработчики могли позже разобраться, но процесс создания/обновления предложения в основной БД должен завершиться успешно.

## Критерии выполнения (Definition of Done)

-   \[ \] В проекте создан `AiIntegrationModule` с настроенным HTTP-клиентом.
-   \[ \] При создании или обновлении предложения (через API или Discord) триггерятся соответствующие доменные события.
-   \[ \] `AiIntegrationService` перехватывает эти события и делает POST-запрос на URL, указанный в `.env`.
-   \[ \] Если выключить или сломать AI-микросервис (замокать ошибку соединения), основное приложение продолжает штатно работать (ошибка только в логах).
