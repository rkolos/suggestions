# Технологический стек микросервиса Suggestions

Документ фиксирует утверждённый технологический стек. Все перечисленные технологии обязательны к использованию в данном микросервисе.

---

## 1. Core (Ядро приложения)

| Технология | Версия | Обоснование |
|------------|--------|-------------|
| **Среда выполнения** | Node.js LTS (рекомендуется v20.x) | Стабильная LTS-ветка для продакшена. |
| **Язык программирования** | TypeScript ^5.x | Строгая типизация. Обязательно использование режима `strict: true` в `tsconfig.json` для предотвращения ошибок типов на этапе компиляции. |
| **Фреймворк** | NestJS ^10.x | Строгая модульная архитектура (out-of-the-box), внедрение зависимостей (DI), отлично подходит для реализации паттернов Domain-Driven Design (DDD). |

---

## 2. Данные и хранение

| Технология | Версия | Обоснование |
|------------|--------|-------------|
| **Основная БД** | PostgreSQL v15.x или выше | Надёжное хранение реляционных данных, поддержка строгих ограничений (уникальные индексы для защиты от накрутки голосов), JSONB для гибких настроек компаний. |
| **ORM** | Prisma ORM | Лучшая типизация на рынке, удобный механизм миграций, интуитивно понятный синтаксис схем (`schema.prisma`). |
| **Кэш и очереди** | Redis ^7.x, BullMQ (`@nestjs/bullmq`) | Redis: Rate Limiting (защита кнопок голосования в Discord от спама) и кэширование. BullMQ: гарантированная доставка фоновых задач (retries), изоляция тяжёлых операций (синхронизация с AI, публикация в Discord, ленивая синхронизация профилей) от основного потока. |

---

## 3. Интеграции

| Технология | Версия | Обоснование |

## Политика версий

- В `package.json` зависимости фиксируются через **caret** (`^`), например: `^10.x`, `^14.x`. Допустимы минорные и патч-обновления в рамках указанного мажора.
- Идентичность сборок между средами обеспечивается **lockfile**: `package-lock.json` (npm) или `pnpm-lock.yaml` (pnpm). Коммитить lockfile в репозиторий обязательно.
- Проверка согласованности версий в CI осуществляется через lockfile; отдельная проверка `engines` в Definition of Done не требуется.

## Рекомендация: блок `engines` в package.json

После инициализации проекта (например, `nest new` или ручная настройка) рекомендуется добавить в `package.json` блок `engines`, чтобы ограничить версию Node.js и выбранного пакетного менеджера для всех разработчиков:

```json
"engines": {
  "node": ">=20.0.0",
  "pnpm": ">=8.0.0"
}
```

Либо для npm:

```json
"engines": {
  "node": ">=20.0.0",
  "npm": ">=9.0.0"
}
```

Выбор пакетного менеджера (pnpm или npm) — на усмотрение команды; единый менеджер должен быть зафиксирован в проекте.
